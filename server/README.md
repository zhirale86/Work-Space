# Сервер системы документооборота

Node.js 22, TypeScript (strict), Fastify 5, PostgreSQL 16 через `pg` (без ORM), проверка запросов — zod.
Архитектурные решения — `docs/02-architecture.md`, справочник API — `docs/04-api.md`,
контракт типов для интерфейса — `src/api-types.ts`, установка на сервер — `deploy/README.md`.

## Структура

| Каталог | Содержимое |
|---|---|
| `migrations/` | пронумерованные SQL-миграции (`001_init.sql`), применяются `npm run migrate` |
| `src/app.ts` | сборка приложения: сессия, защита от CSRF, заголовки безопасности, обработка ошибок, статика интерфейса |
| `src/server.ts` | запуск HTTP-сервера и фоновых заданий |
| `src/auth/` | вход, сессии, пароли (scrypt), точка расширения `AuthProvider` для корпоративного входа |
| `src/documents/` | карточки документов, единое правило видимости (`access.ts`), списки и поиск |
| `src/approvals/` | запуск, решения, маршрут, отмена, напоминания |
| `src/orders/` | утверждение приказов, ознакомление, архив |
| `src/tasks/` | поручения |
| `src/files/` | приём, проверка и выдача файлов; хранилище на диске (`FILES_DIR`), точка расширения `FileScanner` (антивирус) |
| `src/bitrix/` | адаптер Битрикс24: `mock.ts` (эмулятор на таблицах `mock_*`), `rest.ts` (входящий вебхук), очередь синхронизации `sync.ts` |
| `src/notifications/`, `src/reports/`, `src/admin/`, `src/audit/` | уведомления, главная и отчёты, администрирование, журнал действий |
| `src/jobs/` | фоновые задания |
| `src/seed.ts` | начальные и демонстрационные данные; `src/create-admin.ts` — первичная настройка без демо-данных |
| `test/` | интеграционные тесты (`node:test` + `fastify.inject`) |

## Локальная разработка

### PostgreSQL

Используется локальный кластер PostgreSQL 16 на порту 5433 (пользователь `docflow` / пароль `docflow`,
базы `docflow` — разработка, `docflow_test` — тесты). Если кластер не отвечает:

```bash
su postgres -c "/usr/lib/postgresql/16/bin/pg_ctl -D /srv/pg/data -o '-p 5433' -l /srv/pg/pg.log start -w"
```

Создание баз с нуля (под суперпользователем):

```sql
CREATE ROLE docflow LOGIN PASSWORD 'docflow' CREATEDB;
CREATE DATABASE docflow OWNER docflow;
CREATE DATABASE docflow_test OWNER docflow;
```

Права `CREATEDB` нужны тесту резервного копирования: он создаёт и удаляет базу `docflow_restore_test`.

### Команды

```bash
npm ci
npm run build        # компиляция в dist/
npm run migrate      # применить миграции
npm run seed         # справочники, тестовые учётные записи, демо-данные (идемпотентно)
npm start            # http://localhost:3000, API — /api/*
npm test             # все тесты (база docflow_test очищается!)
npm run create-admin -- admin "Фамилия Имя Отчество"   # рабочая установка без демо-данных
```

`npm run dev` — сборка и запуск одной командой. Собранный интерфейс (`../web/dist`, либо `WEB_DIST`) сервер
отдаёт сам, если каталог существует; иначе работает только API.

Проверка после запуска:

```bash
curl -s -c /tmp/c -H 'X-Requested-With: docflow' -H 'Content-Type: application/json' \
     -d '{"login":"petrova","password":"Test12345!"}' http://localhost:3000/api/auth/login
curl -s -b /tmp/c http://localhost:3000/api/dashboard
```

## Фоновые задания

Выполняются внутри процесса сервера (`src/jobs/scheduler.ts`), если `JOBS_ENABLED=true`; все безопасны
для повторного выполнения, одно задание не запускается повторно, пока не закончился предыдущий запуск.

| Задание | Период | Что делает |
|---|---|---|
| Синхронизация с Битрикс24 | 15 с (+ немедленная попытка после каждого изменения) | берёт записи `bitrix_links` в состоянии `pending`/`error` с наступившим временем, блокирует (`FOR UPDATE SKIP LOCKED`) и передаёт **актуальный** статус документа; при ошибке — повтор через 1, 5, 15, 60 мин и запись в журнал |
| Проверка сроков | 5 мин | «Срок приближается» (за 24 ч) и «Срок нарушен» — по одному уведомлению на участника, от которого ожидается действие (ключ `dedupe_key`) |
| Очистка сессий | 1 ч | удаляет истёкшие сессии и старые записи о неудачных попытках входа |

## Битрикс24: переключение `BITRIX_MODE`

- `mock` (по умолчанию) — встроенный эмулятор: сделки в `mock_deals`, задачи согласований в `mock_tasks`.
  Страница сделки эмулятора (`/bitrix-mock/deals/<id>`, API `GET /api/bitrix-mock/deals/:id`) показывает задачи
  со ссылками на карточки — стенд для сценариев 8–11 приёмки. Администратор включает режим «Битрикс24
  недоступен» (`PUT /api/admin/bitrix/mock`), может удалить или закрыть задачу эмулятора для проверки
  восстановления записи.
- `rest` — боевой портал через входящий вебхук. Задайте `BITRIX_WEBHOOK_URL` (права вебхука: `crm`, `task`),
  `BITRIX_PORTAL_URL`, `BITRIX_RESPONSIBLE_ID`. Используются `crm.deal.list`, `crm.deal.get`,
  `tasks.task.list` (поиск по `XML_ID` = маркер `DOCFLOW-<id документа>`), `tasks.task.add`
  (привязка `UF_CRM_TASK = ["D_<id сделки>"]`), `tasks.task.update`. Адрес вебхука в ответы API и журнал
  не попадает. Перед переключением на боевой портал проверьте на кастомизированном Битрикс24, что задачи
  с `UF_CRM_TASK` отображаются в сделке, — способ отображения изолирован в адаптере (`src/bitrix/adapter.ts`).

После переключения режима перезапустите сервер. Связи документов с задачами (`bitrix_links`) хранят
идентификаторы задач конкретного режима; при переходе с эмулятора на боевой портал их нужно очистить
(`UPDATE bitrix_links SET external_task_id = NULL, state = 'pending'`) — записи будут созданы заново
(поиск по маркеру не допустит дублей).

## Тесты

`npm test` компилирует `src/` и `test/` и запускает `node --test` последовательно по файлам. Каждый файл
перед запуском пересоздаёт схему базы `docflow_test` и применяет миграции и справочники; каждый тест
создаёт себе пользователей и документы сам. Фоновые задания в тестах выключены — синхронизация
с Битрикс24 вызывается явно.

| Файл | Что проверяет |
|---|---|
| `acceptance.test.ts` | критерии приёмки 1–16 (раздел 22 ТЗ), каждый отдельным тестом |
| `backup.test.ts` | критерий 17: реальный прогон `deploy/backup.sh` → `deploy/restore.sh` в чистую базу и каталог, запуск приложения на восстановленных данных |
| `approvals.test.ts` | одновременные решения, последовательный маршрут, идемпотентность, комментарии, блокировка файлов, повторный запуск, замена участников |
| `files.test.ts` | сигнатуры, макросы, размер, права на скачивание, лимиты |
| `bitrix.test.ts` | недоступность Битрикс24, сбой после создания, удалённая и закрытая задача, две карточки на сделку |
| `bitrix-rest.test.ts` | модульный тест REST-адаптера с подменой `fetch` |
| `misc.test.ts` | блокировка сотрудника, ознакомление, поручения, сроки, поиск и счётчики, нумерация при параллельном создании |

Для тестов нужны `pg_dump`, `pg_restore`, `psql` версии 16 и права `CREATEDB` у пользователя базы.
